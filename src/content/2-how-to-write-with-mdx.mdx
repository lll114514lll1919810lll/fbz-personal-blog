  title: "用 MDX 写文章的正确姿势",
  date: "2026-10-06",
  publishedAt: "2026-10-06T09:00",
  description: "这个博客的文章格式、元信息写法、配图方式，以及 MDX 和普通 Markdown 的区别。",

}

这个博客的文章都放在 `src/content/` 目录下，每篇就是一个 `.mdx` 文件。

## 文件名就是网址

文件名去掉 `.mdx` 就是这篇的 slug，直接拼在 `/blog/` 后面。目录里的文件带 `1-`、`2-`
这样的数字前缀，那是为了在编辑器里按顺序排列，**前缀本身也是网址的一部分**：

```text
1-hello-world.mdx            →  /blog/1-hello-world
2-how-to-write-with-mdx.mdx  →  /blog/2-how-to-write-with-mdx
```

前缀不会被自动去掉。所以改文件名等于改网址，已经发出去的链接会失效——真要改的话，
记得顺手处理一下旧地址。

## 文件头是必须的

```mdx
export const metadata = {
  title: "文章标题",
  date: "2026-10-05",
  publishedAt: "2026-10-05T14:30",
  description: "一句话摘要，会显示在列表页和分享卡片上",
  tags: ["建站", "技术"],
}
```

这里用的是 **JavaScript 导出**，不是常见的 YAML frontmatter（`---` 包裹的那种）。原因是 `@next/mdx` 原生就支持这种写法，不需要额外装解析 frontmatter 的库。

几个字段的说明：

- `title` — 必填，文章标题
- `date` — 必填，格式 `YYYY-MM-DD`，用于排序
- `publishedAt` — 可选，ISO 8601 时间戳（如 `2026-10-05T14:30`）
- `description` — 建议填，列表页摘要和 SEO 描述都用它
- `tags` — 可选，标签页会按它归类
- `draft` — 可选，设为 `true` 时这篇不会出现在列表和构建产物里

排序是先比 `publishedAt`，没填的退回 `date`；两者都相同再按 slug 排，保证顺序稳定。
所以**只写 `date` 也够用**，`publishedAt` 是留给「同一天发好几篇」时定先后的。

## 正文里不要写一级标题

注意上面的示例正文没有 `# 一级标题`。因为文章页的页头已经渲染了 `metadata.title`，
正文再写一遍标题就会出现两个一模一样的大标题。

正文从`## 二级标题`或普通段落开始就行。

## 日期格式不能写错

必须是 `2026-10-05`，不能写 `2026/10/05` 也不能写 `2026年10月5日`。排序逻辑是按字符串比较的，格式不统一会导致顺序错乱。

## 支持的 Markdown 语法

除了常规语法，这些都能用：

**表格**

| 语法 | 效果 |
| --- | --- |
| `**加粗**` | **加粗** |
| `*斜体*` | *斜体* |
| `~~删除线~~` | ~~删除线~~ |
| `` `行内代码` `` | `行内代码` |

> 表格、删除线、任务列表这些是 GFM 扩展语法，
> 由 `remark-gfm` 插件支持，已经配好了。

表格不只能列语法，也适合整理配置和对比方案。例如把文章元信息写成一张速查表：

| 字段 | 是否必填 | 示例 | 用途 |
| --- | --- | --- | --- |
| `title` | 是 | `用 MDX 写文章` | 页面标题和文章列表标题 |
| `publishedAt` | 否 | `2026-10-06T09:00` | 同一天发布多篇文章时排序 |
| `description` | 建议 | `介绍文章内容` | 列表摘要和 SEO 描述 |
| `tags` | 否 | `["建站", "技术"]` | 把文章归入标签页 |

也可以用来做发布前检查，让读者一眼看出每项工作的状态：

| 检查项 | 状态 | 说明 |
| --- | --- | --- |
| 元信息 | 已完成 | `title`、`date` 已填写 |
| 正文标题 | 已完成 | 没有重复的一级标题 |
| 配图说明 | 待检查 | 确认 `alt` 能描述图片内容 |
| 构建预览 | 未开始 | 发布前在浏览器里检查排版 |

如果需要在正文里比较几种方案，也可以把优缺点放进表格：

| 写法 | 优点 | 限制 |
| --- | --- | --- |
| Markdown 表格 | 简单、可读、无需组件 | 不适合复杂交互 |
| `<figure>` 配图 | 适合截图和流程图 | 需要准备图片文件 |
| React 组件 | 可以做动态数据和交互 | 需要额外编写组件 |

## 还能直接写哪些控件

MDX 允许在正文里写 JSX，所以 HTML 的原生控件也能直接使用。它们适合做设置说明、参数预览和可展开的补充内容，不需要额外导入组件：

<details>
  <summary>展开查看一组原生控件</summary>

  <fieldset>
    <legend>发布设置</legend>

    <label>
      <input type="checkbox" defaultChecked />
      已完成校对
    </label>

    <label>
      <input type="radio" name="visibility" value="public" defaultChecked />
      公开
    </label>
    <label>
      <input type="radio" name="visibility" value="draft" />
      草稿
    </label>

    <label>
      分类
      <select defaultValue="tech">
        <option value="tech">技术</option>
        <option value="life">生活</option>
      </select>
    </label>

    <label>
      摘要
      <textarea defaultValue="这是一段可以直接编辑的摘要。" rows={3} />
    </label>
  </fieldset>
</details>

像 `<details>`、复选框、单选框、下拉框和文本框这样的控件由浏览器直接提供行为。数字进度也可以这样写：

<label>
  构建进度
  <progress value={72} max={100}>72%</progress>
</label>

<label>
  存储空间
  <meter min={0} max={100} low={60} high={85} optimum={30} value={68}>
    68%
  </meter>
</label>

这里的 `defaultChecked` 和 `defaultValue` 是 JSX 写法，表示初始值；不要把它们误写成 HTML 中依赖布尔值的字符串。原生控件只能处理浏览器自带的交互，如果要点击按钮后修改文章内容、请求接口或保存状态，就需要编写一个带 `"use client"`的 React 组件，再在 MDX 中导入它。

## 怎么配图

图片放到 `public/` 里，正文用 `<figure>` 把图片和图注包在一起：

```mdx
<figure className="post-figure">
  <img
    src="/images/my-post/step-1.jpg"
    alt="easy-proxies 仪表盘，显示池内端口 27 个、失败 5 个"
    width={1800}
    height={989}
  />
  <figcaption>图 1：导入订阅后自动测速的结果。</figcaption>
</figure>
```

`src` 写 `/images/...` 就对应仓库里的 `public/images/...`。建议按文章分目录放，
不要都堆在 `public/` 根下。

四个容易踩的点：

- **`className="post-figure"` 不能省。** 配图样式挂在 `.post-figure` 上，而不是挂在 `figure` 上——代码高亮插件也会用 `<figure>` 来包代码块，写成泛匹配会把代码块的外边距一起改掉。
- **`<img>` 要自己闭合**（` />`）。MDX 按 JSX 解析，这里不是 HTML。
- **`width` / `height` 建议写上。** 浏览器拿它预留位置，图片加载完之前页面不会跳动。
- **`alt` 要认真写。** 它既是图片加载失败时的替代文字，也是屏幕阅读器读出来的内容。

图注里可以嵌 `<code>` 这类标签，但**不要写 Markdown**——`<figure>` 内部按 JSX 解析，
`**加粗**` 不会生效，得写成 `<strong>加粗</strong>`。

## 小结

写文章这件事现在简化成：新建文件 → 写元信息 → 写正文，配图就多包一层 `<figure>`。
保存后浏览器会自动刷新。
